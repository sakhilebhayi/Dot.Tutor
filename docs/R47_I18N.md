# R-47 interface languages and translated content

Owner: academic agent. Two separate things: the **interface locale** (words on screen) and **content translation** (a resource, course or profile in another language, with provenance). Neither is a matching signal: matching reads teaching languages (`LanguageProfile`).

## 1. Interface locale

- Locales are the active written rows of the `languages` table (BCP 47 codes: en, zu, xh, af, nso, tn, st, ts, ss, ve, nr, pt, fr, sw). South African Sign Language is a teaching language, never an interface locale.
- Strings live in `lang/<code>/<group>.php`. English is the source. A missing key falls back to English (Laravel `fallback_locale`).
- `SetLocale` (pushed onto the `web` group by the provider) resolves, in order: the signed-in user's saved `interface` language, the session choice (guests), `Accept-Language` restricted to locales that have translated strings, English. It sets `Content-Language`.
- `/language` is the switcher (guests and signed-in). A signed-in choice is stored as the user's `interface` language and never becomes a teaching language.

## 2. Coverage, recorded honestly

Coverage is measured by `LocaleCatalogue`: the share of English keys a locale's files translate. `lang/locales.php` records who wrote each locale (`source`, `machine_unreviewed`, `reviewed`) and `interface_fully_keyed`, which stays `false` while screens still hold hard-coded English (all pre-R-47 screens and the operator screens do). While it is false, no locale but English is labelled "fully translated".

| Locale | Keys in `academic.php` | Who wrote it | Switcher label |
|---|---|---|---|
| en | 100% (source) | source | Fully translated |
| af | 100% | R-47 build agent (AI), not reviewed by a native speaker | Partly translated; AI-drafted, not yet checked |
| fr | 100% | same | same |
| pt | 100% | same | same |
| zu, xh, nso, tn, st, ts, ss, ve, nr, sw | 0% | none | Not translated yet, shown in English |

Why no isiZulu, isiXhosa or other South African language strings: the build agent could not stand behind interface translations in those languages without a native speaker's review. A translator adds `lang/<code>/academic.php` with the same keys (a test checks every shipped locale has exactly the English keys) and records the review in `lang/locales.php`. Owner item: commission native-speaker review of af and translations for zu, xh, nso, tn, st first.

Operator screens are English only by design (staff tools); learner-facing strings in this domain are all in `lang/en/academic.php`. Other domains add their own groups; coverage is computed across every group automatically.

## 3. Content translations with provenance

`App\Domain\Academic\Translations`:

- `register(alias, Model::class, [fields])` in the owning domain's provider (academic registers `academic.subject`, `academic.level`, `academic.topic`). The alias, not the class, is stored.
- `put(model, field, locale, body, provenance, translator?, translatorLabel?, machineModel?)`. Provenance `author` (the content's author), `human` (named translator or agency) or `machine` (must name the model). Refuses: unregistered model or field, unknown/signed locale, the original locale, empty text. New text resets the review to `unreviewed`.
- The original stays in the model's own column, in `original_locale` (English when the model has none). `source_hash` marks a translation **out of date** when the original changes.
- `review(translation, reviewer, approved|rejected)`. Rejected translations are never shown.
- `sideBySide(model, field, locale)` returns the original and the translation with provenance label, machine model, translator, review status, out-of-date flag and `notation_missing`.
- `GET /translations/{alias}/{id}/{field}?locale=` serves it as JSON. `academic.*` content is readable by any signed-in user; every other type must pass its own `view` policy.

`NotationGuard` checks that LaTeX segments, expressions (`x^2`, `f(x)=2x+1`, `a^2 + b^2 = c^2`), chemical formulas with digits (H2O, CO2) and numbers survive translation verbatim (a decimal comma and a decimal point are both accepted). It cannot judge meaning; it catches a dropped or rewritten formula and is shown as "check these against the original".

No translation is produced by this domain. Machine translation arrives with the wave-2 AI agent through `put(..., Machine, machineModel: ...)`; the UI must label it.
