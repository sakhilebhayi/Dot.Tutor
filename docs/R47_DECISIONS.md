# R-47 decisions log

Format: `D-n (agent, date): decision. Why.` Each agent appends in its own number block (docs/R47_ARCHITECTURE.md section 1).

D-1 (coordinator, 2026-11-10): Build in waves of parallel agents on worktrees off the trunk `feat/r47-tutor`, as Dot.Ehail R-46 did. Why: the brief spans a dozen domains; one contract plus owned paths lets them proceed in parallel without collisions.
D-2 (coordinator, 2026-11-10): Keep the shared-host constraints: no daemons, polling instead of websockets, cron-driven queue. Why: the live host is shared cPanel, the same as every other Dot app.
D-3 (coordinator, 2026-11-10): The academic structure is data (countries, curricula, frameworks, stages, levels, subject offerings), seeded with CAPS, IEB, a tertiary track and Cambridge. Why: brief section 5 forbids hardcoding one country's system.
D-4 (coordinator, 2026-11-10): Paystack for payments, integer minor units, a double-entry ledger. Why: owner decision 2026-10-18 and the money rules learned on Dot.Ehail and Dot.Finance.
D-5 (coordinator, 2026-11-10): Live lessons are native WebRTC with polling signalling (no TURN yet, honest fallback to the tutor's own meeting link). Why: Dot.Engage proved the approach on the same host; brief section 12 forbids fake video.
D-6 (coordinator, 2026-11-10): AI through an `AiTutor` interface with an Anthropic driver, off until the owner sets a key; Dot.Agents, Dot.Brain and Dot.Memory are not called because no documented cross-app API exists for this use. Why: brief sections 14 and 21 require genuine integrations only.
D-7 (coordinator, 2026-11-10): Minors are protected server-side through one `SafeguardingGate` seam that every talk, meet, pay and publish action asks. Why: brief section 15; one gate is testable and cannot be skipped by a UI.
D-200 (academic, 2026-11-10): The existing `subjects` table is the global subject catalogue (new nullable columns; `App\Domain\Academic\Models\Subject` extends the legacy model). Why: `tutor_subject` and `tutor_sessions` point at `subjects.id` with RESTRICT; one id space keeps every booking valid and lets booking v2 use catalogue subjects directly.
D-201 (academic, 2026-11-10): Legacy rows are adopted (oldest row with a catalogue name), linked (`canonical_subject_id`) or catalogued (given a slug); the legacy `level` string is never rewritten and maps onto levels in every seeded curriculum where the band applies. Why: no row lost, no id changed, and a legacy row does not say which curriculum it meant.
D-202 (academic, 2026-11-10): Reference data is inserted by the idempotent `php artisan academic:sync` (also `AcademicReferenceSeeder`, `DatabaseSeeder`), not by a migration; the deploy must run it after `migrate`. Why: the existing tests assume an empty subject table, a data migration would slow every test, and the sync never overwrites operator edits.
D-203 (academic, 2026-11-10): Curricula with `country_id` null are international and available in every country (Cambridge). Why: the contract says a curriculum belongs to a country, but Cambridge is offered in many.
D-204 (academic, 2026-11-10): Grade R, Second Additional Language and the smaller FET electives are not seeded; operators add them. IEB's extra subject is seeded as "Advanced Programme Mathematics" with "Further Studies Mathematics" as an alias. Why: the brief starts at Grade 1; names the build agent could not confirm are kept to a minimum and flagged for academic review.
D-205 (academic, 2026-11-10): South African Sign Language (`sfs`, modality signed) is seeded as a teaching language and excluded from interface locales. Why: it has been official since 2023; Deaf learners need SASL-teaching tutors; it has no written UI.
D-206 (academic, 2026-11-10): Date of birth is stored as the month only (`birth_month`, 1st of the month) and age banding uses the last day of that month. Why: POPIA minimisation for children; the error is never in the direction of treating a child as older.
D-207 (academic, 2026-11-10): Institutions are asked for at tertiary levels only; no school name is stored for anyone. Why: a school name identifies a minor; matching does not need it.
D-208 (academic, 2026-11-10): Age banding is handed to `Contracts\AgeBandResolver` (default null = unknown) and `LearnerProfiles::birthDateFor()` is the source for safety's `BirthDateSource`; integration binds both. Why: the safety domain owns the rule and was not merged into this branch.
D-209 (academic, 2026-11-10): Audit goes through `Contracts\AcademicAudit`, defaulting to a structured application-log line. Why: the safety Audit store was not on this branch; the contract asks for a no-op-or-better seam.
D-210 (academic, 2026-11-10): Interface translations shipped for af, fr, pt only, written by the build agent (an AI) and labelled "AI-drafted, not checked by a native speaker"; zu and the other SA languages ship with 0% and say so. `interface_fully_keyed = false` stops any locale but English being labelled complete while screens hold hard-coded English. Why: the brief allows only translations the agent can stand behind and requires honest quality labels.
D-211 (academic, 2026-11-10): Accept-Language only selects locales with translated strings; an explicit choice can select any written locale. Why: a header-only switch to a 0% locale changes nothing visible and confuses.
D-212 (academic, 2026-11-10): The NeedParser is deterministic (names, aliases, grade patterns, teaching markers; "en" excluded as a marker because it is Afrikaans "and"); an unmarked language name is returned both as language subjects and as a "possible" teaching language. Why: no AI in wave 1; ambiguity is shown, not guessed.
D-213 (academic, 2026-11-10): Translations store an alias registered per domain, not a class name, and refuse machine translations without a model name; a new text resets review; rejected translations are hidden; `source_hash` marks stale ones. Why: brief section 10/22 provenance and honesty.
D-214 (academic, 2026-11-10): Operator screens for the structure are one generic controller and view driven by `OperatorResources`; rows are deactivated, never deleted. Why: nine resources with the same shape; wave-2 ops UI restyles one view.
D-215 (academic, 2026-11-10): Academic JSON endpoints validate themselves and answer `{error, message}` with 422, because `bootstrap/app.php` renders JSON errors only under `api/*` (a shared file this agent does not edit). Why: architecture section 2 error contract.
